# 検証結果

## 初回リリースの受け入れ

利用者の実アカウントで54アルバムの保存を確認し、2026-11-12 に E2E を受け入れ済みです。その実行では1アルバムの申告16,983件に対して取得16,982件の差があり、レポートに記録されました。アルバム選択画面とアルバム別 JSONL の追加後は、Windows の模擬実行で個別選択、キャンセル、同名ファイルの出力を確認しています。

Windows 11 x64、Rust/Cargo 1.72.0（MSVC）、Node.js 26.13.0、Chrome 156 を使用しました。検証開始時の D ドライブ空き容量は約461 GB でした。

| 一覧、所属のページネーション | 複数ページ、反復トークン、件数不一致、空アルバム、同名アルバムと同名ファイルを模擬応答で確認しました。同じメディア ID は複数アルバムに保持され、同一アルバム内の重複はエラーになりました。 |
| アルバムの選択と JSONL | Windows PowerShell 5.1 のフォームで全件・個別選択、検索時の選択保持、キャンセルを確認しました。模擬取得で、同名の別アルバムを個別に選べること、ファイル名の衝突回避、一括 JSON と JSONL の内容照合、レポート保存失敗時のファイルの片付けを確認しました。 |
| アカウント、認証切れ、形式変更 | アカウント不一致、リクエスト中の切り替え、サインインへの移動、不正エンベロープ、所属応答のアルバム ID 不一致を模擬しました。 |
| CDP・再試行 | 実際のローカル WebSocket で、CDP セッション ID、画像ブロック指示、一時エラー後の再試行、無応答時のタイムアウトを確認しました。 |

| 申告件数より少ないアルバム | 所属一覧の最後まで取得したうえで件数が少ない場合に、その件数をレポートに記録し、次のアルバムを保存することを模擬テストで確認しました。次回に不足分が取得できた場合も、取得済みの詳細バッチを再利用しました。 |
| 専用ブラウザの起動競合 | 起動中の専用 Chrome 157 で、CDP 起動前に終了手順を表示することを確認しました。模擬プロファイルで RUN の終了コード 1 と FAILED レポートを確認し、ロック解除後は検査に通ることも単体テストで確認しました。 |
| 進捗表示 | Windows のリリース実行ファイルと模擬ブラウザを使い、個別照会を14秒待つ間も経過時間、残りの目安、最後の更新からの時間が表示されることを確認しました。応答後に全7アルバムが保存され、SUCCESS が表示されました。 |
