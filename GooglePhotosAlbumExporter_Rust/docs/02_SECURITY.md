# 安全性

- 専用ブラウザを起動し、通常の Chrome / Edge プロファイルと重なるパスを拒否します。アプリが作成した専用フォルダは所有マーカーで識別し、従来の既定専用フォルダも使えます。ブラウザ起動時は拡張機能を無効にします。
- SETUP は通常のブラウザウィンドウを開きます。ログイン、CAPTCHA、二段階認証は利用者の操作です。RUN は認証を確認できない場合に停止します。
- RUN の CDP は OS が割り当てたローカルポートに限定します。起動したプロセスが生存し、専用プロファイルの DevToolsActivePort が更新された場合に限って 127.0.0.1 に接続します。WebSocket パスとメッセージ長を検証し、操作終了時に専用ブラウザを閉じます。同一 PC のプロセスは実行中のローカル CDP へアクセスできるため、信頼できる PC と専用プロファイルで実行してください。
- セッション Cookie はブラウザが同じ Google フォトのオリジンに送信します。ページが持つリクエスト値と共有アルバム閲覧キーはブラウザ側オブジェクト内で使い、Rust へ返す値は検証ステータスとメタデータに限ります。資格情報を読み出す CDP コマンドは呼び出しません。
- 読み取り RPC を一覧、所属、詳細バッチ、単件詳細の4種類に限定します。送信先、引数の構造、HTTP メソッドを実装内で固定し、リダイレクトを追跡しません。CDP の取得用タブは Image / Media リクエストをブロックします。ログイン用の SETUP ウィンドウでは通常の画面表示が行われます。
- HTTP 429、または待機時間を示す `Retry-After` ヘッダー付きの HTTP 503 を受信した場合は、その実行を停止します。時間を置いてから再実行してください。
- Google フォトの可視アカウント表示を前後で照合し、同じページのアカウントスロットとセッションの継続を確認します。照合の信頼性は Google フォトの表示とページ状態に依存します。
- 出力先と専用フォルダの既存パス構成要素にあるシンボリックリンク・ジャンクションを拒否します。出力名にアルバム名や ID を直接使わず、既存の確定ファイルの上書きを拒否します。チェックポイントはアカウント別で、実行ロックで同じ出力先への同時書き込みを抑えます。
- 出力 JSON とチェックポイントにはアルバム名や ID、ファイル名、メールアドレスが含まれます。保存フォルダへのアクセスは利用者が管理してください。

参照 [Chrome のローカルデバッグ制限](https://developer.chrome.com/blog/remote-debugging-port) · [DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/)
